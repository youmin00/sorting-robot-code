===============================================================================
0. 이 문서의 목적과 읽는 방법
===============================================================================

이 문서는 부품 사양이나 세부 보정값을 나열하는 문서가 아니다.
현재 프로젝트에서 카메라, PC 프로그램, 컨베이어 STM32, 로봇팔 STM32,
두 로봇팔과 흡착 장치가 어떤 순서로 정보를 주고받고 함께 작동하는지를
설명하는 문서다.

팀원이 GPT나 다른 AI에게 프로젝트 관련 문서, 발표 자료, 설명문, 순서도,
개선안 등을 요청할 때 이 파일의 내용을 먼저 제공하면 된다.

AI가 이 프로젝트를 해석할 때 지켜야 할 핵심 전제는 다음과 같다.

- 이 시스템의 상위 판단 주체는 PC의 Python 통합 프로그램이다.
- 컨베이어 STM32와 로봇팔 STM32는 서로 직접 판단을 주고받지 않는다.
  PC가 두 장치 사이에서 상태와 명령을 중계한다.
- 물체 인식은 학습형 AI나 YOLO가 아니라 RealSense 컬러/깊이 영상과
  OpenCV 기반의 기하·깊이 규칙으로 이루어진다.
- 현재 분류 기준은 물체의 색상이 아니라 큐브 크기, 즉 3 cm와 5 cm다.
- 흰색처럼 보이는 정도는 검출 후보의 신뢰도를 보조할 뿐 분류 종류가 아니다.
- 로봇팔은 카메라 좌표를 직접 해석하지 않는다. PC가 좌표를 로봇 관절 계획으로
  바꾼 뒤 STM32에 전달한다.
- 한 번 촬영한 좌표만 믿고 모든 물체를 연속 처리하지 않는다. 물체를 처리할
  때마다 남은 작업영역을 다시 촬영하고 다시 계획한다.
- 안전성과 충돌 회피 때문에 양팔 동시 작업과 교차 순차 작업을 상황에 따라
  선택한다.

세부 핀 번호, 각도, 거리, 통신 속도, 보정값이 필요한 경우에는
"문서/전체_시스템_설명.txt"와 실제 소스 코드를 함께 참고한다.


===============================================================================
1. 프로젝트를 한 문장으로 설명하면
===============================================================================

컨베이어가 큐브를 카메라 작업구역까지 운반하면 RealSense 카메라가 큐브의
위치와 높이를 측정하고, PC가 각 큐브를 담당할 로봇팔과 안전한 관절 경로를
결정한 뒤, 두 로봇팔이 흡착으로 큐브를 집어 크기별 위치에 놓고 컨베이어를
다시 출발시키는 자동 반복 분류 시스템이다.

2. 전체 구조와 각 구성요소의 책임
===============================================================================

[RealSense D435 카메라]
        |
        | 컬러 영상 + 깊이 영상
        v
[PC Python 통합 프로그램]
   |                         |
   | 벨트 상태/검사 요청      | 관절 계획/완료 응답
   v                         v
[컨베이어 STM32]          [로봇팔 STM32]
   |                         |
   | STEP 모터, PA15 센서     | 왼팔/오른팔 서보, 흡착 출력
   v                         v
[컨베이어 벨트]           [양팔 + 공압 흡착기]

2-1. PC Python 통합 프로그램

전체 시스템의 조정자다. 다음 일을 한곳에서 연결한다.

- 카메라 시작과 영상 수신
- 작업영역의 물체 검출
- 검출 결과의 프레임 간 안정성 확인
- 물체 중심의 실제 좌표와 높이 계산
- 3 cm 또는 5 cm 큐브 판정
- 왼팔 또는 오른팔의 작업영역 판정
- 각 팔의 접근, 접촉, 예압, 상승 자세 계산
- 두 팔을 동시에 움직일지 교차 파이프라인으로 움직일지 결정
- 컨베이어 STM32와 로봇팔 STM32에 각각 명령 전송
- 완료, 오류, 긴급정지, 리셋 상태 관리

2-2. 컨베이어 STM32

벨트를 실제로 움직이고 작업구역 마커를 감지하는 하위 제어기다.

- STEP 펄스를 만들어 컨베이어 모터를 구동한다.
- PA15 센서가 다음 작업구역의 흰색 선 또는 벽 마커를 감지하면 벨트를 멈춘다.
- 벨트를 멈춘 직후 PC에 CHECK를 보내 카메라 검사를 요청한다.
- PC가 E를 보내면 다음 작업구역으로 다시 이동한다.
- PC가 O를 보내면 물체가 있다는 뜻이므로 정지 상태를 유지한다.
- 재출발 직후 같은 마커를 다시 감지해 즉시 멈추지 않도록, 기존 마커를 완전히
  벗어난 다음에만 다음 정지를 허용한다.

2-3. 로봇팔 STM32

PC가 계산한 동작 계획을 실제 관절 움직임과 흡착 순서로 실행하는 하위 제어기다.

- 왼팔과 오른팔의 각 관절을 PWM으로 제어한다.
- 관절을 시작 각도에서 목표 각도까지 부드럽게 보간한다.
- 여러 관절과 양팔이 같은 동작 단계에 맞춰 도착하도록 함께 움직인다.
- 접근, 접촉, 예압, 흡착, 상승, 분류 위치 이동, 해제, 복귀를 실행한다.
- 동작 도중에도 정지나 복귀 명령을 확인한다.
- 현재 명령을 받을 수 있는지 검사하고 PLAN_OK, BUSY, ERROR 등의 상태를 보낸다.
- 작업 단계가 끝나면 DONE, HOLDING, CROSS_DONE, PLACED 같은 결과를 PC에 보낸다.

2-4. 두 로봇팔과 공압

- 왼팔은 카메라 기준 한쪽 절반의 작업영역을 담당한다.
- 오른팔은 반대쪽 절반을 담당한다.
- 두 팔은 마주보는 형태로 설치되어 있으므로 오른팔 계획을 만들 때 좌표계를
  180도 회전해 오른팔의 로컬 좌표로 바꾼다.
- 각 팔은 자기 흡착 채널을 독립적으로 켜고 끈다.
- 큐브를 잡을 때는 단순히 표면에 닿는 데서 끝내지 않고, 접촉 후 약간 눌러
  흡착이 안정될 수 있는 예압 단계를 거친다.


===============================================================================
3. 시스템 전체 상태 흐름
===============================================================================

정지 대기
  -> 사용자가 s 입력
  -> 컨베이어 이동
  -> 작업구역 마커 감지
  -> 컨베이어 정지 및 CHECK 전송
  -> 카메라 검출과 좌표 안정화
  -> 도달 가능한 물체 존재 여부 판단
     -> 없음: E 전송 후 컨베이어 이동
     -> 있음: O 전송 후 컨베이어 정지 유지
  -> 물체별 로봇팔 계획 생성
  -> 양팔 동시 작업 또는 교차 순차 작업 실행
  -> 로봇팔 완료 응답 수신
  -> 남은 물체 재촬영 및 재계획
  -> 작업영역이 빌 때까지 반복
  -> 여러 프레임에서 빈 상태 재확인
  -> E 전송
  -> 다음 작업구역으로 컨베이어 이동

이 흐름에서 중요한 점은 컨베이어가 움직이는 동안 로봇팔이 임의로 작업을
시작하지 않는다는 것이다. 센서가 벨트를 멈추고 CHECK를 보낸 뒤에만 PC가
해당 구역의 물체를 판단한다. 반대로 PC도 로봇 작업이 끝나고 작업영역이
비었다고 확인하기 전에는 컨베이어를 다시 출발시키지 않는다.


===============================================================================
4. 프로그램 시작부터 자동운전 진입까지
===============================================================================

1) PC 프로그램이 RealSense 카메라를 찾고 사용할 영상 프로파일을 연다.

2) 깊이 영상을 컬러 영상 좌표에 맞추고, 사용할 카메라 내부 파라미터와
   깊이 단위를 저장한다. 설정된 경우 깊이 노이즈를 줄이는 필터도 준비한다.

3) PC가 컨베이어 STM32와 로봇팔 STM32의 시리얼 포트를 각각 연다.

4) 현재 기본 설정에서는 프로그램이 켜졌다고 벨트가 바로 출발하지 않는다.
   컨베이어는 정지한 상태로 시작하고 프리뷰 창에서 s 입력을 기다린다.

5) 사용자가 s를 누르면 PC가 컨베이어 STM32에 자동 시작 명령을 보낸다.
   이때 과거 검출 결과와 슬롯 예약을 비워 이전 작업구역의 정보가 새 구역에
   섞이지 않게 한다.

6) 컨베이어 STM32는 자동 모드를 켜고 벨트를 움직인다.


===============================================================================
5. 컨베이어 정지와 카메라 검사 요청
===============================================================================

컨베이어 STM32는 벨트가 움직이는 동안 작업구역 마커 센서를 감시한다.
마커가 유효하게 감지되면 다음과 같이 행동한다.

1) STEP 펄스를 중단해 벨트를 정지한다.
2) PC에 CHECK라는 한 줄 메시지를 보낸다.
3) 카메라 판단 결과를 기다리는 상태로 들어간다.

PC는 CHECK를 받기 전에는 자동 분류용 검출 결과를 계속 유지하지 않는다.
벨트가 이동할 때 생기는 영상 흔들림이나 지나가는 물체를 작업 대상으로
오해하지 않도록, CHECK 시점에 검출을 활성화하고 정지 장면을 새로 본다.


===============================================================================
6. 카메라가 물체를 찾는 방식
===============================================================================

카메라 처리는 단일 색상 임계값 하나로 끝나지 않는다. 서로 다른 장면과 표면에
대응하기 위해 여러 후보 생성 방법을 합치고, 기하학과 깊이 조건으로 잘못된
후보를 걸러낸다.

6-1. 입력 정리

- 컬러 영상과 깊이 영상을 같은 픽셀 위치가 같은 공간을 가리키도록 정렬한다.
- 깊이 영상에는 시간 방향과 공간 방향 필터를 적용해 흔들림과 빈 픽셀을 줄인다.
- 물체 수가 적은 설정에서는 화면 중심 작업영역을 우선 보고, 여러 물체 설정에서는
  전체 화면을 더 넓게 검색할 수 있다.

6-2. 컨베이어 상판 기준면 추정

- 깊이 분포에서 넓고 연속된 배경 영역을 찾아 컨베이어 상판으로 본다.
- 상판이 카메라에 완전히 평행하지 않을 수 있으므로 가능하면 하나의 평면 모델로
  근사한다.
- 이후 각 픽셀이 상판보다 얼마나 위에 있는지를 계산할 수 있다.
- 이 기준면은 물체 높이 계산과 배경 제거의 공통 기준으로 쓰인다.

6-3. 물체 후보 생성

프로그램은 다음 종류의 후보를 함께 사용한다.

- 상판보다 위로 올라온 깊이 영역
- 알려진 큐브 높이와 가까운 상단면 깊이 영역
- 가까운 깊이 층과 주변 배경 사이의 차이
- 깊이 영상의 경계
- 컬러 영상의 사각형 경계
- 어두운 물체를 놓치지 않기 위한 어두운 덩어리 후보

따라서 흰 큐브만 찾는 시스템도 아니고, 컬러 영상만 사용하는 시스템도 아니다.
깊이 정보가 정상일 때는 깊이 기반 후보가 중심이 되고, 표면 반사나 낮은 질감으로
깊이가 약할 때는 컬러 경계와 어두운 물체 후보가 보조한다.

6-4. 후보 검증과 점수화

후보가 실제 큐브 상단면인지 확인하기 위해 다음 성질을 함께 본다.

- 너무 작거나 화면 대부분을 차지하지 않는가
- 영상 또는 검사영역 경계에 붙은 배경 윤곽이 아닌가
- 사각형에 가까운가
- 지나치게 길쭉하지 않은가
- 후보 내부에 유효한 깊이값이 충분한가
- 상단면 깊이가 한 평면처럼 고른가
- 후보 내부가 주변보다 실제로 위로 올라와 있는가
- 면의 방향이 옆면보다 상단면에 가까운가
- 이전 프레임에서 보던 물체 위치와 자연스럽게 이어지는가
- 화면 중심과의 관계, 후보 면적, 직사각형 충실도 등이 적절한가

흰색 상단면은 후보 점수에 가산점을 받을 수 있지만, 흰색 여부만으로 물체를
확정하지 않는다. 모든 후보는 종합 점수로 정렬되며, 서로 겹치거나 같은 물체를
중복 표현하는 후보는 하나로 합쳐진다.

6-5. 붙어 있는 여러 큐브 처리

같은 높이의 큐브가 맞닿아 하나의 큰 깊이 덩어리로 보일 수 있다. 프로그램은
예상되는 큐브 상단 크기, 형상의 긴 방향, 내부 거리 봉우리 등을 이용해 하나의
연결 영역을 여러 물체 후보로 나누려고 시도한다.


===============================================================================
7. 프레임 간 추적과 좌표 안정화
===============================================================================

검출된 물체는 매 프레임 새 번호를 무작위로 받지 않는다. 이전 프레임의 사각형과
새 후보의 위치를 비교해 가능한 한 같은 슬롯, 즉 같은 객체 번호를 유지한다.

- 가까운 이전 위치와 새 후보를 전체적으로 가장 자연스럽게 연결한다.
- 잠깐 검출이 끊겨도 최근 슬롯을 바로 다른 물체가 빼앗지 않게 보호한다.
- 모서리와 중심이 조금 흔들릴 때는 완화해 표시와 좌표가 튀지 않게 한다.
- 선택 옵션인 좌표 잠금 기능을 켜면 정지한 물체의 좌표를 고정하고, 실제 이동이
  여러 프레임 이어질 때만 잠금을 푼다.
- 로봇 작업 중인 객체 슬롯은 예약해 순간적인 누락 때문에 다른 객체로 바뀌는
  일을 줄인다.

로봇 명령을 만들기 전에는 단지 "한 프레임에서 보였다"는 조건만 사용하지 않는다.
연속 프레임에서 물체 수가 같고, 물체들의 실제 좌표가 허용 범위 안에서 유지되는지
확인한다. 객체 번호 순서가 바뀌더라도 실제 위치 집합이 같으면 같은 장면으로 본다.

좌표가 계속 흔들리면 임의의 좌표로 로봇을 출발시키지 않고 경고를 출력한 뒤
다시 안정 장면을 기다린다. 이 대기 중에도 종료, 긴급정지, 리셋 입력은 받을 수 있다.


===============================================================================
8. 영상 좌표가 로봇 작업 정보가 되는 과정
===============================================================================

검출된 사각형 하나는 다음 순서로 로봇이 사용할 수 있는 객체 정보가 된다.

1) 사각형 중심 픽셀과 상단면의 대표 깊이를 구한다.

2) RealSense 카메라 내부 파라미터를 사용해 픽셀을 카메라 기준 3차원 위치로
   역투영한다.

3) 컨베이어 상판 평면까지의 깊이와 큐브 상단 깊이의 차이로 물체 높이를 구한다.

4) 카메라 중심을 원점으로 하는 작업 좌표로 정리한다. 화면 오른쪽이 +X,
   화면 위쪽이 +Y가 된다.

5) 설치 오차와 실제 장비 시험으로 얻은 축척·오프셋 보정을 적용한다.

6) 물체 높이가 3 cm와 5 cm 중 어느 쪽에 가까운지 판정한다.

결과적으로 각 객체는 대략 다음 정보를 가진다.

- 객체 슬롯 번호
- 영상 중심 위치
- 카메라가 본 거리
- 로봇 작업 좌표 X, Y
- 상판 기준 물체 높이 Z
- 3 cm 또는 5 cm 크기 판정


===============================================================================
9. 어느 팔이 어떤 물체를 담당하는가
===============================================================================

두 팔은 카메라 중심선을 기준으로 작업영역을 나눠 가진다.

- 한쪽 Y 영역은 왼팔이 담당한다.
- 반대쪽 Y 영역은 오른팔이 담당한다.
- 중심선 위의 물체는 현재 규칙상 왼팔 쪽으로 들어간다.
- 중심 좌표만 영역 안에 있다고 바로 허용하지 않는다. 큐브 크기의 절반까지
  고려해 물체 전체가 팔의 안전 작업영역 안에 들어와야 한다.
- 좌우 방향 역시 로봇이 실제로 닿을 수 있도록 제한된 범위 안이어야 한다.

오른팔은 왼팔과 마주보도록 설치되어 있으므로, 전역 카메라 좌표를 그대로 넣지
않는다. 오른팔용 계획을 만들 때 좌표를 180도 회전한 로컬 좌표로 변환하고,
오른팔에만 필요한 설치 보정을 적용한 뒤 같은 역기구학 계산 구조를 사용한다.

작업영역 밖에 있는 물체는 로봇이 억지로 잡으려 하지 않는다. 해당 정지 구역에
도달 가능한 물체가 하나도 없고 작업영역 밖 물체만 있다면, 경고를 남기고
컨베이어를 다음 구역으로 이동시킨다.


===============================================================================
10. 한 물체에 대한 로봇팔 계획 생성
===============================================================================

PC는 객체 좌표를 바로 하나의 관절 각도로 바꾸지 않는다. 한 번의 피킹에 필요한
여러 자세를 각각 계산한다.

- 접근: 흡착기가 큐브 위쪽 안전 높이까지 이동하는 자세
- 접촉: 흡착기가 큐브 상단면에 닿는 자세
- 예압: 흡착 패드가 밀착되도록 조금 더 눌러 주는 자세
- 상승: 흡착 후 큐브를 장애물에서 들어 올리는 자세

각 단계마다 역기구학으로 가능한 관절 조합을 찾고, 관절 범위와 목표 위치 오차를
검사한다. 네 단계 중 하나라도 안전하게 도달할 수 없으면 그 물체 계획 전체를
버리고 로봇에 보내지 않는다.

실제 장비에서는 순수한 수학적 위치와 흡착기의 실제 접촉 위치가 완전히 같지 않다.
그래서 접근·접촉·예압 자세, 좌우 위치, 오른팔 설치 방향, 작업영역 끝부분 등에
실기 보정이 추가된다. 이 보정은 검출과 분류 판단 뒤, 최종 관절 명령을 만들 때
적용된다.

반복되는 비슷한 좌표의 역기구학 계산은 캐시에 저장해 다음 계산을 빠르게 한다.
다만 캐시에서 계획을 가져와도 현재 프레임의 실제 카메라 좌표 정보는 갱신한다.


===============================================================================
11. 여러 물체 중 처리 순서를 고르는 방식
===============================================================================

PC는 왼팔 영역과 오른팔 영역의 도달 가능한 물체를 따로 모은다. 각 영역에서는
로봇 기준으로 가까운 물체를 우선 후보로 선택한다.

그다음 두 후보의 위치 관계를 보고 두 가지 실행 전략 중 하나를 선택한다.

11-1. 일반 양팔 동시 작업

두 팔의 경로가 중앙에서 서로 간섭할 위험이 낮으면 양팔 계획을 한 번에 보낸다.
양쪽에 물체가 있으면 두 팔이 함께 집고 함께 분류 위치로 이동한다. 한쪽에만
물체가 있으면 해당 팔만 움직이고 다른 팔은 안전 자세에서 기다린다.

동시 작업 중 두 팔이 물체를 들어 카메라 작업영역 밖으로 빠져나오면 로봇팔
STM32가 PC에 CAMERA_CLEAR를 먼저 보낸다. PC는 로봇팔이 분류 상자에 물체를
놓고 복귀하는 동안 카메라로 남은 작업영역을 미리 촬영하고 다음 역기구학 계산을
준비한다. 이후 STM32가 DONE을 보내면 이미 준비된 다음 장면으로 바로 이어갈 수 있다.

즉, 이 모드에서는 "로봇 놓기 시간"과 "다음 장면 인식 시간"이 일부 겹친다.

11-2. 중앙 충돌 위험 시 교차 순차 파이프라인

양쪽 후보가 모두 중앙 위험 구역에 있고 서로 충분히 떨어져 있지 않으면 두 팔을
동시에 중앙으로 넣지 않는다. 이때는 교차 파이프라인을 사용한다.

첫 단계:

- 우선순위가 선택된 한 팔만 물체를 집는다.
- 다른 팔은 로딩 자세에서 기다린다.
- 집은 팔은 물체를 든 채 로딩 자세로 돌아온다.
- STM32가 HOLDING을 보내 현재 한 팔이 물체를 들고 있음을 PC에 알린다.

다음 단계:

- 물체를 들고 있던 팔은 자기 분류 위치로 이동한다.
- 그와 동시에 반대쪽 빈 팔은 다음 물체를 집으러 간다.
- 한쪽은 기존 물체를 놓고, 반대쪽은 새 물체를 흡착한다.
- 두 팔은 다시 로딩 자세로 모이며 새 물체를 든 팔이 바뀐다.
- STM32가 CROSS_DONE을 보내 교차 한 단계가 끝났음을 알린다.

이 과정을 좌우로 번갈아 반복하면 중앙에 두 팔이 동시에 들어가는 것을 피하면서도,
한 팔의 놓기와 다른 팔의 집기를 겹쳐 처리할 수 있다.

더 이상 반대쪽에서 집을 물체가 없으면 PC가 빈 교차 명령을 보내 현재 들고 있는
물체만 안전하게 놓게 한다. STM32는 PLACED로 마지막 놓기 완료를 알린다.

11-3. 우선순위의 의미

중앙 위험 물체가 여러 개면 단순히 항상 왼팔부터 시작하지 않는다. 좌우에 남은
중앙 후보 개수와 직전 선호 방향을 이용해 시작 팔을 고르고, 작업이 끝날 때마다
선호 방향을 바꾸어 한쪽만 계속 우선되는 현상을 줄인다.


===============================================================================
12. 로봇팔 STM32가 계획을 실행하는 실제 의미
===============================================================================

PC가 보내는 계획에는 물체 크기와 접근·접촉·예압·상승에 필요한 관절 목표가
포함된다. STM32는 먼저 값의 형식과 관절 허용 범위를 검사한다.

명령이 유효하고 로봇이 비어 있으면 PLAN_OK를 보내고 실행 대기 상태에 넣는다.
이미 다른 동작 중이면 BUSY를 보내며, 형식이나 범위가 잘못되면 ERROR를 보낸다.

일반적인 피킹 실행은 다음 의미를 가진다.

1) 팔을 로딩 자세로 정렬한다.
2) 몸통 회전 관절을 대상 방향으로 향하게 한다.
3) 상부 접근 자세로 이동한다.
4) 큐브 상단에 접촉한다.
5) 예압 자세로 조금 눌러 흡착 준비를 한다.
6) 해당 팔의 흡착을 켠다.
7) 상승 자세로 큐브를 들어 올린다.
8) 먼저 팔의 상하 관절을 접고, 그다음 몸통을 회전해 충돌 가능성을 줄인다.
9) 큐브 크기에 대응하는 분류 위치로 이동한다.
10) 놓기 자세에서 흡착을 끈다.
11) 몸통 방향을 유지한 채 상하 관절부터 접는다.
12) 마지막에 몸통을 로딩 방향으로 돌린다.
13) 완료 상태를 PC에 보낸다.

3 cm와 5 cm의 놓기 방향은 팔마다 서로 반대로 배치되어 있다. 따라서 "작은 큐브는
무조건 같은 J1 방향"이 아니라, 큐브 크기와 어느 팔인지가 함께 놓기 위치를 결정한다.


===============================================================================
13. 한 물체 처리 후 반드시 다시 보는 이유
===============================================================================

로봇팔이 물체를 집는 동안 다음 변화가 생길 수 있다.

- 가려져 있던 다른 큐브가 새로 보일 수 있다.
- 붙어 있던 큐브의 윤곽이 달라질 수 있다.
- 로봇 동작이나 흡착 때문에 주변 물체가 조금 움직일 수 있다.
- 이전 프레임의 객체 번호와 실제 남은 물체가 더 이상 일치하지 않을 수 있다.

그래서 PC는 한 번 만든 전체 목록을 끝까지 소모하지 않는다. 로봇 완료 응답을
받으면 과거 추적 슬롯과 후보를 정리하고, 실제 남은 장면이 안정될 때까지 다시
촬영한다. 그런 다음 왼팔/오른팔 작업영역 판정과 관절 계획을 새로 수행한다.

일반 양팔 동시 작업에서는 CAMERA_CLEAR 시점부터 이 재촬영을 미리 시작할 수 있고,
교차 파이프라인에서는 각 HOLDING 또는 CROSS_DONE 단계 뒤 실제 작업영역을 다시 본다.


===============================================================================
14. 작업영역이 비었다고 판단하는 방식
===============================================================================

현재 목록에 물체가 없다고 한 번 나온 것만으로 컨베이어를 바로 출발시키지 않는다.
마지막 분류 후 여러 프레임을 추가로 확인하고, 연속해서 빈 장면이 유지되어야
EMPTY가 확인된 것으로 취급한다.

- 재확인 도중 물체가 다시 보이면 분류 루프로 돌아간다.
- 좌표가 빠졌거나 아직 도달 가능한 물체가 있다면 다시 안정 좌표를 측정한다.
- 도달 가능한 물체는 없고 작업영역 밖 물체만 남았다면 이를 경고하고 다음
  작업구역으로 넘긴다.
- 정말 비었다면 PC가 컨베이어 STM32에 E를 보낸다.
- 컨베이어 STM32는 E를 받을 당시 카메라 응답 대기 상태여야만 벨트를 재시작한다.

따라서 E는 단순한 모터 시작 키가 아니라 "현재 정지 구역의 카메라/로봇 처리가
끝났으므로 다음 구역으로 이동해도 된다"는 완료 확인 신호다.


===============================================================================
15. 두 STM32와 PC 사이의 핵심 메시지 의미
===============================================================================

15-1. 컨베이어 STM32 관련

- S: 자동 반복 시작. 벨트를 움직이고 센서 정지를 기다린다.
- CHECK: 컨베이어가 PC에 보내는 카메라 검사 요청이다.
- O: PC가 보낸 "도달 가능한 물체가 있음" 신호다. 벨트 정지를 유지한다.
- E: PC가 보낸 "현재 구역 처리 완료 또는 유효 물체 없음" 신호다. 벨트를 재시작한다.
- X: 자동 모드를 끄고 벨트를 정지한다.
- R: 컨베이어만 수동 재출발한다.

15-2. 로봇팔 STM32 관련

- M 계획: 양팔 동시 실행용이다. 한쪽 계획만 포함할 수도 있다.
- D 계획: 한 팔 보유 상태를 이어 가는 교차 순차 파이프라인용이다.
- P 계획: 왼팔 단일 동적 피킹용으로 펌웨어에 남아 있다.
- T 계획: 오른팔 경로를 공압 없이 시험하기 위한 용도다.
- PLAN_OK: 명령을 정상적으로 해석해 실행 대기열에 넣었다.
- CAMERA_CLEAR: 집은 물체가 카메라 작업영역을 벗어나 다음 장면을 봐도 된다.
- DONE: 일반 양팔 작업 전체가 완료되었다.
- HOLDING: 교차 파이프라인 첫 팔이 물체를 든 채 대기한다.
- CROSS_DONE: 기존 물체 놓기와 반대 팔의 새 물체 집기가 함께 끝났다.
- PLACED: 더 집을 물체 없이 마지막 보유 물체만 놓았다.
- BUSY: 이전 동작 중이라 새 계획을 받을 수 없다.
- ERROR: 명령 형식, 값, 상태 또는 실행 과정에 문제가 있다.
- X: 동작을 중단하고 양쪽 흡착을 끄는 긴급정지다.
- H: 현재 작업을 취소하고 양팔을 안전 기본 자세로 복귀시키는 리셋 명령이다.
- r: 양팔을 로딩 자세로 이동시킨다.

PC는 계획을 보낸 뒤 단순한 시간 지연만 두고 성공했다고 가정하지 않는다.
STM32의 최종 완료 응답을 기다린 뒤 다음 판단으로 넘어간다.


===============================================================================
16. 사용자 키와 운전 제어
===============================================================================

- s: 정지 상태에서 컨베이어 자동 작업을 시작한다.
- x: 컨베이어와 로봇팔에 긴급정지를 요청한다.
- z: 전체 작업 흐름을 처음 상태로 되돌린다.
- p: 현재 통합 코드에서는 가장 가까운 큐브를 집는 키가 아니다. 양팔을 로딩
  자세로 보내는 수동 명령이다.
- q 또는 ESC: 프로그램을 종료한다.

주의: 통합 Python 파일 맨 위의 오래된 사용 설명에는 p가 가장 가까운 큐브를
보낸다고 적혀 있지만, 현재 실제 preview() 구현은 p 입력 시 로봇 STM32에 r을
보내 양팔을 로딩 자세로 이동시킨다. 자료를 만들 때 실제 구현을 기준으로 해야 한다.


===============================================================================
17. 긴급정지, 리셋, 통신 오류의 차이
===============================================================================

17-1. x 긴급정지

- PC가 컨베이어 STM32와 로봇팔 STM32 양쪽에 X를 보낸다.
- 컨베이어 자동 모드와 벨트 이동을 멈춘다.
- 로봇팔은 실행 요청을 취소하고 양쪽 흡착을 끈다.
- 로봇팔 STM32의 EMERGENCY_DONE 응답을 기다린다.
- 긴급정지 후 자동으로 다시 시작하지 않는다.

흡착도 꺼지므로 물체를 들고 있을 때는 낙하 가능성을 고려해야 한다.

17-2. z 전체 리셋

- 우선 컨베이어를 정지하고 입력 버퍼를 정리한다.
- 로봇팔에 H를 보내 진행 중 계획을 취소하고 안전 복귀시킨다.
- 카메라 추적 슬롯, 예약 객체, 후보 목록을 모두 초기화한다.
- RealSense 파이프라인 자체를 중지했다가 다시 시작한다.
- 리셋이 끝나도 컨베이어는 정지 상태이며 사용자가 s를 눌러야 다시 시작한다.

즉, x는 즉시 위험을 끊는 동작이고 z는 장치와 소프트웨어 상태를 운전 시작점으로
다시 맞추는 복구 동작이다.

17-3. 로봇팔 응답 시간 초과

PC가 로봇팔 완료 응답을 받지 못하면 로봇에 연속으로 새 명령을 덮어쓰지 않는다.
컨베이어만 정지시켜 현재 작업구역을 유지하고, 로봇팔의 현재 자세와 공압 상태는
추가 명령 없이 유지하려고 한다. 운영자가 실제 상태를 확인한 뒤 x 또는 z로
정리해야 한다.

17-4. 일부 장치 연결 실패

- 컨베이어 포트가 없으면 카메라 프리뷰는 가능하지만 자동 컨베이어 흐름은 없다.
- 로봇팔 포트가 없으면 카메라 검출은 가능하지만 물체가 있는 구역에서 자동 분류를
  진행할 수 없어 벨트를 정지 상태로 유지한다.
- 카메라 프레임이 일시적으로 끊기면 프로그램은 즉시 종료하지 않고 대기 화면과
  경고를 표시한다. z 리셋은 카메라 파이프라인 재시작까지 포함한다.

20. 현재 시스템을 설명할 때 자주 생기는 오해
===============================================================================

오해 1: 카메라가 로봇팔에 직접 좌표를 보낸다.

실제: 카메라는 PC에 영상만 제공한다. PC가 물체를 찾고 좌표와 관절 계획을 계산해
로봇팔 STM32에 보낸다.

오해 2: 센서가 물체를 감지하면 로봇이 바로 움직인다.

실제: PA15 센서는 작업구역 마커를 감지해 벨트를 멈추고 CHECK를 보낼 뿐이다.
실제 물체 존재와 위치는 정지 후 카메라가 판단한다.

오해 3: 컨베이어 STM32가 로봇팔 STM32를 직접 제어한다.

실제: 두 STM32 사이의 직접 제어 연결이 핵심 구조가 아니다. PC가 컨베이어 상태를
받고 로봇 작업을 지시한 뒤 다시 컨베이어 재출발을 허가한다.

오해 4: 두 팔은 항상 동시에 같은 동작을 한다.

실제: 안전하면 동시 작업하고, 중앙 충돌 위험이 있으면 한 팔의 놓기와 반대 팔의
집기를 엇갈리게 하는 교차 파이프라인을 사용한다. 한쪽에만 물체가 있으면 한 팔만
움직일 수도 있다.

오해 5: 처음 검출된 모든 좌표를 저장해 순서대로 처리한다.

실제: 매 처리 단계 뒤 카메라가 남은 장면을 다시 측정하고 계획을 갱신한다.

오해 6: 흰색 큐브와 검은색 큐브를 색상별로 분류한다.

실제: 현재 최종 분류 기준은 높이로 판정한 3 cm와 5 cm 크기다. 색상 정보는
검출 후보를 찾고 점수를 보조하는 데만 쓰인다.

오해 7: 머신러닝 모델이 물체를 인식한다.

실제: 현재 저장소에는 학습 모델 추론 과정이 없다. 깊이 분리, 윤곽, 사각형,
평면성, 프레임 연속성 같은 규칙 기반 비전이다.

오해 8: 화면에 표시되는 개수가 생산 누적 통계다.

실제: 화면의 크기별 개수는 현재 보이는 장면 기준이다. 작업구역의 processed_count도
해당 정지 구역 처리 중에만 쓰이며 영구 생산 통계로 저장되지 않는다.

21. 현재 구현의 중요한 운영상 특징과 한계
===============================================================================

- 기본 추적 설정은 한 장면에서 최대 4개 객체를 대상으로 하며 실행 옵션으로 늘릴
  수 있지만, 무한한 수의 물체를 처리하는 구조는 아니다.
- 물체 좌표가 안정되지 않으면 안전을 위해 계속 재측정한다. 따라서 조명, 깊이 반사,
  카메라 진동이 심하면 처리 시간이 길어질 수 있다.
- 도달 불가능한 물체는 역기구학 단계에서 제외된다. 검출되었다고 모두 집는 것은 아니다.
- 컨베이어의 구역 이동은 시간으로 강제 정지하는 방식이 아니라 다음 유효 센서 마커
  감지를 기준으로 한다.
- PC와 STM32의 시리얼 메시지는 줄 단위의 단순 프로토콜이며, 로봇팔 쪽은 수신 안정성을
  위해 현재 바이트 간 전송 간격을 유지한다.
- 통합 프로그램은 로봇 완료 메시지를 받아야 다음 단계로 넘어간다. 통신이 끊기면
  자동으로 성공 처리하지 않는다.
- 긴급정지는 흡착을 해제한다. 정지 버튼의 의미를 "현재 자세 그대로 안전 유지"로
  설명하면 안 된다.
- 응답 시간 초과 시의 보존 전략과 사용자가 누르는 x 긴급정지는 서로 다르다.
- 별도의 영구 작업 이력, 생산량 데이터베이스, 웹 대시보드, PLC 연동은 현재 핵심
  실행 코드에 포함되어 있지 않다.


===============================================================================
22. 기능 간 유기적 연결을 가장 짧게 요약한 설명
===============================================================================

컨베이어 센서가 "촬영할 위치에 도착했다"는 사건을 만든다.
그 사건을 받은 PC가 카메라를 통해 "무엇이 어디에 있는가"를 만든다.
비전 결과가 안정되면 작업영역 판단이 "어느 팔이 담당하는가"를 만든다.
역기구학이 그 담당 정보를 "어떻게 움직일 것인가"라는 단계별 관절 계획으로 바꾼다.
양팔 스케줄러가 두 계획의 공간 관계를 보고 "동시에 할지 엇갈려 할지"를 결정한다.
로봇팔 STM32가 계획을 실제 PWM과 흡착 순서로 실행하고 완료 상태를 PC에 돌려준다.
PC는 완료를 근거로 카메라 장면을 새로 만들고 남은 물체를 다시 판단한다.
빈 상태가 연속해서 확인되면 PC가 컨베이어에 다음 구역 이동을 허가한다.

즉, 센서 -> 인식 -> 안정화 -> 좌표화 -> 팔 배정 -> 경로 계획 -> 양팔 조율
-> 실제 동작 -> 완료 확인 -> 재인식 -> 컨베이어 재출발이 하나의 폐루프를 이룬다.

23. 이 내용을 AI에게 줄 때 함께 사용할 수 있는 요청문 예시
===============================================================================

예시 1 - 발표 자료 작성

"아래 프로젝트 시스템 흐름 설명을 기준으로 발표 자료의 목차와 슬라이드별 핵심
메시지를 작성해 줘. 부품 스펙 나열보다 컨베이어 센서, 카메라 인식, PC 판단,
양팔 스케줄링, STM32 실행, 재확인이 어떻게 폐루프로 연결되는지 강조해 줘."

예시 2 - 보고서 작성

"아래 설명을 바탕으로 시스템 구성과 동작 원리를 보고서 문체로 작성해 줘.
현재 구현에 없는 딥러닝, PLC, 데이터베이스 기능을 임의로 추가하지 말고,
양팔 동시 모드와 중앙 충돌 방지용 교차 파이프라인의 차이를 자세히 설명해 줘."

예시 3 - 순서도 작성

"아래 설명에서 실제 자동운전 상태만 추출해 Mermaid 순서도와 상태도로 만들어 줘.
CHECK, O, E, PLAN_OK, CAMERA_CLEAR, DONE, HOLDING, CROSS_DONE, PLACED의 송신 주체와
수신 주체를 틀리지 않게 표시해 줘."

예시 4 - 개선안 검토

"아래 현재 구조를 유지하면서 처리량을 높일 수 있는 개선안을 제안해 줘.
안전성, 중앙 충돌 회피, 매 작업 후 재촬영, STM32 응답 확인을 훼손하지 않는 범위에서
비전 처리와 로봇 동작의 겹침을 늘리는 방향으로 분석해 줘."
