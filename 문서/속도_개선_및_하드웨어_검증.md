# 작업 속도 개선 및 하드웨어 검증

## 하드웨어 없이 적용한 안전한 개선

### 1. 로봇팔 각도 계산 최적화

기존과 동일하게 관절 각도를 0.5도 간격으로 검사하지만, Python 반복문 대신 NumPy로 한 번에 계산한다.

- 변경 전 양팔 새 좌표 계산: 약 0.85초
- 변경 후 양팔 새 좌표 계산: 약 0.011초
- 대표 좌표에서 기존 방식과 J1~J4, 기울기 선택 결과가 같은지 자동 검사한다.
- 기존 2 mm 좌표 캐시는 그대로 유지한다.

### 2. 사용하지 않는 깊이 화면 생성 생략

기본 설정인 `show_depth_panel=False`에서는 화면에 표시하지 않을 깊이 컬러맵을 매 프레임 만들지 않는다. 물체 검출에는 원본 깊이값을 계속 사용하므로 검출 방식은 바뀌지 않는다.

### 3. 통신 안전값 유지

로봇팔 STM32로 보내는 글자 사이의 20 ms 간격은 `ARM_SERIAL_BYTE_DELAY_SEC` 상수로 분리했지만 기본값은 바꾸지 않았다. 실제 장비 없이 이 값을 낮추면 명령 일부가 유실될 수 있다.

### 4. 로봇팔 코드 분리 및 중복 제거

- `sorting_robot/arm_planning.py`: 작업영역 판단, 각도 계산, 양팔 계획 선택
- `sorting_robot/arm_protocol.py`: STM32 명령 문자열 생성과 안전 전송
- 통합 실행 파일에서 `continue` 뒤에 있어 실행될 수 없던 과거 중복 코드 183줄을 제거했다.

분리 전과 같은 함수와 명령을 사용하므로 조인트 속도, 이동 순서, 서보 지연, 공압 순서는 바뀌지 않는다. STM32 제어 코드도 수정하지 않았다.

### 5. 카메라 후보 검사 범위 축소

물체 후보마다 848×480 전체 마스크를 여러 장 만들던 방식을 물체 주변의 작은 영역만 처리하도록 변경했다. 컬러 영상의 흑백 변환과 흐림 처리도 한 프레임에서 한 번만 수행한다.

- 합성 두 물체 장면의 검출 좌표, 깊이, 화면 결과가 변경 전과 동일한지 자동 검사한다.
- 현재 PC의 합성 장면 처리시간은 프레임당 약 50~60 ms다.
- 실제 카메라 영상의 개선 폭은 물체 수와 배경에 따라 달라질 수 있다.

카메라 설정은 `sorting_robot/camera_config.py`, 깊이 화면 변환은 `sorting_robot/vision_display.py`, 사각형 보조 계산은 `sorting_robot/vision_geometry.py`로 분리했다. 설정값과 검출 기준은 변경하지 않았다.

## 하드웨어 없이 확인하는 방법

자동 검사:

```powershell
.\.venv312\Scripts\python.exe -m unittest discover -s tests -v
```

각도 계산 속도 측정:

```powershell
.\.venv312\Scripts\python.exe ".\도구\로봇팔_각도_속도측정.py"
```

카메라 검출 속도 측정:

```powershell
.\.venv312\Scripts\python.exe ".\도구\카메라_검출_속도측정.py"
```

## 실제 장비가 생긴 뒤의 시험 순서

1. 현재 20 ms 통신 간격으로 좌우 팔 각각 10회 이상 시험한다.
2. 전송 명령과 STM32의 `PLAN_OK` 응답 시간을 기록한다.
3. STM32 UART를 인터럽트 또는 DMA 버퍼 방식으로 개선한다.
4. 그 후에만 통신 간격을 10 ms, 5 ms, 2 ms 순서로 낮춰 본다.
5. 각 단계에서 명령 100회 연속 전송, `ERROR`·누락 0회인지 확인한다.
6. 비상 정지 `X`, 복귀 `H`, 공압 해제가 모든 단계에서 정상인지 확인한다.

통신 속도, 서보 이동 지연, 카메라 안정 프레임 수를 한 번에 바꾸지 않는다. 하나를 바꿀 때마다 좌표 정확도와 충돌 여부를 먼저 확인한다.
